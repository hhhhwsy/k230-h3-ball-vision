# 庐山派 K230 钢球识别：数据采集与训练流程

## 当前情况

没有 `.kmodel` 时，识别程序不能运行。完整过程是：

1. 用最终比赛使用的 K230 摄像头拍摄钢球。
2. 给每张图中的每个钢球画检测框，类别统一为 `steel_ball`。
3. 训练 YOLOv8n，得到 `best.pt`。
4. 导出 ONNX，再用与板端固件匹配的 nncase 转成 `.kmodel`。
5. 把 `.kmodel` 上传到 TF 卡，运行检测程序。

## 一、用 K230 拍照

打开 `k230_capture_steel_ball_v122.py`，在 CanMV IDE 中运行：

- 屏幕和 IDE 显示实时画面。
- 每按一次开发板侧面的 USER 用户键，保存一张照片。
- 保存位置：`/sdcard/steel_ball_dataset/images/raw/`。
- 文件名如：`steel_ball_000000.jpg`。
- 按 `Ctrl+C` 停止。

该代码按标准版庐山派 K230 编写，用户键为 GPIO53。若是 Lite K230D，需要把按键、LED 配置改为 GPIO64、GPIO65。

拍完后，在 CanMV IDE/Web 左侧设备文件中找到上述目录，把 `raw` 文件夹下载到电脑。

## 二、应该拍多少张

第一版建议至少准备：

- 500～800 张含钢球的正样本。
- 100～200 张完全没有钢球的负样本；负样本不画框，但必须保留空标签文件。
- 每张可以出现 1～8 个球；相互接触时仍要给每个可见球分别画框。

采集时要覆盖：

- 比赛场地真实背景、灯光和相机安装高度。
- 近、中、远距离，尤其是远处只有十几个像素的小球。
- 单球、多球、部分遮挡、相互接触、画面边缘的球。
- 强反光、阴影、过曝、较暗环境和不同拍摄角度。
- 与钢球相似的干扰物：螺丝、轴承、灰色圆点、灯光反射等。

不要让“手掌背景”占数据集的大多数。你给的手机照片可以保留为少量补充样本，但模型最终应主要学习比赛场地中由 K230 摄像头拍到的钢球。

## 三、标注规则

可使用 AnyLabeling、CVAT、LabelImg 或 Roboflow，导出 YOLO 格式：

- 只建立一个类别：`steel_ball`。
- 框紧贴球的可见外缘，不要包含大块背景。
- 五个球就画五个框；重叠的球不要用一个大框包起来。
- 被遮住超过一半且无法确定边界的球，可以不标。
- 所有清晰可见的球都必须标出，漏标会严重影响训练。

标注后目录应类似：

```text
steel_ball_dataset/
├─ images/
│  ├─ train/
│  ├─ val/
│  └─ test/
└─ labels/
   ├─ train/
   ├─ val/
   └─ test/
```

每张图片必须有同名 `.txt` 标签，例如：

```text
images/train/steel_ball_000123.jpg
labels/train/steel_ball_000123.txt
```

## 四、下一步交给 Codex

采集完成后，把以下内容压缩成 ZIP 发给 Codex：

- K230 拍摄的原始图片。
- 已标注的图片和 YOLO 标签；如果尚未标注，也可以先发一批样本检查拍摄质量。
- 说明比赛时摄像头大约离球多远、画面中最多有几个球。
- 固件终端第一行版本信息；你当前截图显示的是 CanMV v1.2.2。

Codex 接下来可以继续完成：

1. 检查漏标、错误框和重复图片。
2. 按场景划分 train/val/test，避免连续近重复照片泄漏到验证集。
3. 训练 YOLOv8n 并评估漏检、误检。
4. 导出 ONNX。
5. 按 v1.2.2 固件对应的 nncase 版本转换 KModel。
6. 修改 `D:\k230\codex` 中的板端识别代码并核对实际输出。
