# K230 实时图传与传统视觉预留方案

配套代码：`k230_rtsp_vision_ready_v1_8.py`

目标平台：立创·庐山派 K230-CanMV，当前固件 `CanMV v1.8-21` 或兼容的 v1.8+ 固件。

## 1. 实现目标

这套程序将 K230 的摄像头分成两条硬件输出通道：

```text
摄像头
  ├─ 通道 0：1280×720 YUV420SP
  │            ↓
  │         H.264 硬编码
  │            ↓
  │         RTSP / Wi-Fi
  │            ↓
  │         OBS 显示和录像
  │
  └─ 通道 1：640×360 RGB565
               ↓
            传统视觉算法
               ↓
          钢球中心 x / 速度
```

K230 不保存视频文件。OBS 负责显示和手动录像，传统视觉以后在 K230 本地执行，RTSP 不进入控制闭环。

这样做的原因：

- H.264 图传由硬件编码器完成，不需要 Python 搬运原始 720p 图像。
- 视觉识别使用独立的低分辨率通道，避免每帧处理 1280×720 图像。
- Wi-Fi 或 OBS 延迟不会影响后续钢球控制。
- K230 不同时写 SD 卡，减少存储阻塞和资源竞争。

## 2. 使用前必须完成的配置

打开代码并修改：

```python
WIFI_SSID = "你的 2.4 GHz 热点名称"
WIFI_PASSWORD = "你的热点密码"
```

必须满足：

1. K230 和运行 OBS 的电脑连接同一个局域网。
2. 热点启用 2.4 GHz；建议使用电脑热点或独立小路由器。
3. 热点不能开启“AP 隔离/客户端隔离”。
4. Windows 防火墙需要允许 OBS 访问专用网络。
5. 启动程序后等待完整的 8 秒网络稳定倒计时。
6. 终端出现“视觉预留型图传已启动”后再打开 OBS。

## 3. 默认参数及理由

| 参数 | 默认值 | 说明 |
|---|---:|---|
| 传感器模式 | 1920×1080@30 | 避免部分传感器在低分辨率模式自动运行到 60/90 fps |
| 图传分辨率 | 1280×720 | 能清晰覆盖整个约 25 cm 管道，便于观察钢球 |
| 图传帧率 | 30 fps | 每 33.3 ms 一帧，兼顾视觉响应与无线稳定性 |
| 编码格式 | H.264 Baseline | OBS/VLC 兼容性较好，无 B 帧，实时性较好 |
| 图传码率 | 2000 kbps | 俯视固定画面通常足够清晰，2.4 GHz Wi-Fi 压力适中 |
| GOP | 30 | 每秒约一个关键帧，客户端加入和断流恢复较快 |
| VENC 缓冲 | 8 | 吸收短时调度抖动，避免缓冲过少导致丢帧 |
| 视觉通道 | 640×360 RGB565 | 足够做 ROI、阈值、连通域或圆检测，计算量明显更低 |
| Wi-Fi 稳定等待 | 8 秒 | DHCP 成功后继续验证链路和 IP 没有变化 |

### 为什么推荐 30 fps

后续需要从连续帧计算钢球位置与速度。30 fps 的采样间隔约为 33 ms，通常足以用于管道滚球的视觉测量，同时不会像 60 fps 那样显著增加：

- 摄像头和 ISP 带宽；
- H.264 编码压力；
- Wi-Fi 码率和包调度压力；
- 传统视觉算法的计算压力。

只有当 30 fps 实测无法满足控制动态，并且视觉算法、Wi-Fi 与 OBS 均通过压力测试后，才建议尝试 60 fps。

## 4. 参数调整方案

### 4.1 推荐预设

| 使用场景 | 分辨率 | 帧率 | 码率 | GOP |
|---|---:|---:|---:|---:|
| 首次排障/弱 Wi-Fi | 640×480 | 30 | 1000 kbps | 30 |
| 推荐配置 | 1280×720 | 30 | 2000 kbps | 30 |
| 画质优先 | 1280×720 | 30 | 3000 kbps | 30 |
| 60 fps 实验 | 1280×720 | 60 | 3500~5000 kbps | 60 |

修改位置：

```python
SENSOR_MODE_WIDTH = 1920
SENSOR_MODE_HEIGHT = 1080
SENSOR_MODE_FPS = 30

VIDEO_WIDTH = 1280
VIDEO_HEIGHT = 720
VIDEO_FPS = 30
VIDEO_BIT_RATE_KBPS = 2000
VIDEO_GOP = 30
```

尝试 60 fps 时，必须把传感器模式也改成摄像头实际支持的 60 fps 模式。例如传感器支持 `1280×720@60` 时：

```python
SENSOR_MODE_WIDTH = 1280
SENSOR_MODE_HEIGHT = 720
SENSOR_MODE_FPS = 60
VIDEO_FPS = 60
VIDEO_GOP = 60
```

不要只把 `VIDEO_FPS` 改成 60，而保持传感器工作在 30 fps。

### 4.2 视觉通道调整

默认：

```python
ENABLE_VISION_CHANNEL = True
PROCESS_VISION = False
VISION_WIDTH = 640
VISION_HEIGHT = 360
```

含义：视觉通道已经配置好，但当前不执行算法。这样可以先单独完成图传稳定性测试。

开始编写视觉算法时：

1. 实现 `traditional_vision_step(image)`。
2. 将 `PROCESS_VISION` 改成 `True`。
3. 每次处理结束后不要保存 `image` 引用，程序会立即 `del image`。
4. 优先裁剪管道 ROI，再做阈值或圆检测。
5. 算法单帧执行时间应尽量小于 33 ms，才能接近 30 Hz。

如果算法速度不足，按以下顺序优化：

1. 缩小 ROI，只保留管道区域。
2. 将视觉通道降到 `480×272` 或 `320×240`。
3. 使用灰度阈值、连通域和面积/圆度筛选。
4. 降低视觉处理频率，但保持图传 30 fps。
5. 避免在每帧中打印大量日志或主动调用 GC。

### 4.3 曝光调整

首次调试保持：

```python
MANUAL_EXPOSURE_US = 0
```

即使用自动曝光。摄像头、管道和补光灯固定后，如果钢球有明显运动拖影，可尝试：

```python
MANUAL_EXPOSURE_US = 8000
```

建议测试范围约 `6000~10000 us`。曝光越短，拖影越少，但画面越暗、噪声越高。不要直接照搬数值，必须结合现场光照、补光灯和镜头实测。

建议使用左右对称的漫射补光，避免金属钢球产生单点强反光。摄像头应尽量垂直于管道，并固定焦距、安装高度和视场。

### 4.4 零拷贝发送

默认：

```python
PREFER_ZERO_COPY = True
```

程序优先把 VENC 物理地址直接交给 RTSP，减少 Python `bytes` 复制。如果当前固件没有该接口，会自动回退到复制路径。

若出现稳定复现的花屏，可以临时改成：

```python
PREFER_ZERO_COPY = False
```

如果关闭后花屏消失，说明当前固件的物理地址发送路径或缓冲生命周期需要进一步核对；如果仍花屏，应优先检查 Wi-Fi、码率、供电和客户端缓存。

## 5. OBS 设置

程序启动后会输出类似：

```text
RTSP 地址： rtsp://192.168.190.53:8554/ball
```

OBS 操作：

1. “来源”区域点击 `+`。
2. 选择“媒体源”。
3. 取消勾选“本地文件”。
4. “输入”粘贴完整 RTSP 地址。
5. “输入格式”留空。
6. 网络缓冲先保持 `1~2 MB`，稳定后再尝试降低。
7. 先不要启用硬件解码；确认稳定后可以对比测试。
8. 点击“确定”。

录像建议：

- 格式选择 `MKV`，异常断电时比 MP4 更不容易整段损坏。
- 录制结束后可使用 OBS 的“文件 → 录像转封装”转换为 MP4。
- OBS 画布和输出分辨率设为 `1280×720`，避免无意义缩放。
- 帧率设为 `30 fps`。
- 有独立显卡时优先使用 NVENC/QSV/AMD 硬件编码器。

## 6. 常见问题与处理顺序

### 6.1 `SetOutBufs() takes 4 positional arguments but 5 were given`

原因：使用了 CanMV v1.2.2 的旧 VENC 调用方式，而开发板运行的是 v1.8。

本代码已经使用 v1.8 调用：

```python
encoder.SetOutBufs(buffer_count, width, height)
encoder.Create(attributes)
encoder.Start()
encoder.GetStream(stream_data, timeout)
encoder.ReleaseStream(stream_data)
encoder.Stop()
encoder.Destroy()
```

不要再给这些方法传旧版 `venc_chn` 参数。

### 6.2 `Stop() takes 1 positional argument but 2 were given`

同样是旧版 API 问题。v1.8 使用 `encoder.Stop()`，不传通道号。

### 6.3 `warning: sensor not call run()`

通常不是根因，而是编码器初始化先报错，程序进入清理流程时传感器还没运行。先解决它上方出现的第一个真实异常。

### 6.4 Wi-Fi 已连接，但 OBS 黑屏

依次检查：

1. K230 终端是否已经打印“图传已启动”。
2. OBS 是否使用本次启动输出的新 IP，而不是上次的旧地址。
3. 地址是否包含端口和会话：`rtsp://IP:8554/ball`。
4. 电脑和 K230 是否处于同一子网。
5. 热点是否开启客户端隔离。
6. Windows 防火墙是否允许 OBS 访问专用网络。
7. 先用 VLC 打开同一个地址；VLC 也打不开时应排查 K230/网络，而不是 OBS。

### 6.5 能显示但卡顿、延迟不断增加

按此顺序处理：

1. 把码率从 `2000` 降到 `1500` 或 `1000 kbps`。
2. 确认只使用 2.4 GHz 热点支持的稳定信道，并让天线远离电机和金属遮挡。
3. 将图传降到 `640×480@30`。
4. 关闭其他占用热点带宽的设备。
5. 降低 OBS 网络缓冲；过低会导致抖动，需逐级测试。
6. 检查 K230 5 V 供电是否稳定，电机电源噪声不要直接耦合到视觉模块。

### 6.6 花屏、马赛克或偶尔绿屏

可能原因：

- Wi-Fi 丢包或信号弱；
- 码率过高；
- 关键帧间隔过长；
- 物理地址发送路径与当前固件不兼容；
- 供电抖动；
- OBS/VLC 解码缓存设置不合适。

先将 `PREFER_ZERO_COPY=False` 对比，再将码率降到 `1000 kbps`。不要同时改多个参数，否则无法判断根因。

### 6.7 `sensor already inited` 或摄像头被占用

可能有另一份 `/sdcard/main.py` 正在脱机运行，或上一次程序异常结束后媒体资源尚未释放。

处理方法：

1. 停止 IDE 中正在运行的程序。
2. 确认没有重复点击运行。
3. 仍无法恢复时给 K230 完整断电重启。

### 6.8 内存不足或视觉开启后推流不稳定

处理顺序：

1. 保持 `PROCESS_VISION=False`，先验证纯图传。
2. 将视觉通道降低到 `320×240`。
3. 不要把图像加入列表或跨帧保存。
4. 降低图传分辨率或 VENC 缓冲数量。
5. 避免每帧创建大量 Python 对象。

### 6.9 实际帧率明显低于 30 fps

观察终端每 10 秒输出的“推流状态”。如果只开启图传仍低：

- 查看传感器日志是否实际选择了 `1920×1080@30`；
- 检查网络发送是否阻塞；
- 降低码率并关闭零拷贝做对比；
- 确认没有其他程序占用摄像头或 VENC。

如果开启视觉后才降低，说明 `traditional_vision_step()` 超过时间预算，应缩小 ROI 或降低视觉通道分辨率。

## 7. 后续钢球识别建议

摄像头固定在管道正上方后，传统视觉可以按以下流程实现：

```text
视觉通道图像
  ↓
固定管道 ROI
  ↓
灰度或 LAB 阈值
  ↓
形态学去噪
  ↓
连通域/圆度/面积筛选
  ↓
钢球中心 x 像素
  ↓
像素—厘米标定
  ↓
位置与速度估计
```

标定建议：

1. 在管道两端各设置一个固定标定点。
2. 记录两个端点的像素坐标 `x_left`、`x_right`。
3. 已知有效管道长度为 `L_cm`。
4. 将球中心转换为厘米：

```text
position_cm = (ball_x - x_left) × L_cm / (x_right - x_left)
```

摄像头和管道的相对位置固定后，标定参数不要在运行中自动改变。控制程序应使用 K230 本地计算的球位置，不要从 OBS 画面反向识别。

## 8. 上场前测试清单

至少完成一次 30 分钟连续测试：

- [ ] 冷启动能正常连接热点并完成 8 秒等待。
- [ ] OBS 能通过终端输出地址打开画面。
- [ ] 实际帧率长期接近 30 fps。
- [ ] 画面无持续花屏、绿屏或累计延迟。
- [ ] OBS 能录制 MKV，并能正常回放。
- [ ] 关闭并重新启动程序后摄像头不会报占用。
- [ ] 临时关闭热点后程序能释放链路并自动重连。
- [ ] 电机运行、舵机动作时图传不会因供电干扰断开。
- [ ] USER 键长按能安全停止图传。
- [ ] 摄像头覆盖整个管道，并保留约 10%~15% 边缘余量。
